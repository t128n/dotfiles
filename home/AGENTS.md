# Dotfile Notes

- `home/dot-gitconfig` is symlinked to `~/.gitconfig`; editing it changes the live config immediately. `~/.gitconfig-identity` is included from it.
- `home/dot-gitconfig-identity` is a placeholder copied with `create_if_missing = true`. Fill `~/.gitconfig-identity` per machine; the final bootstrap hook prompts until the "Your Name" placeholder is gone. `mise run gitconfig:identity` opens it.
- SSH signing uses `~/.ssh/id_ed25519.pub`. `allowed_signers` is intentionally not managed or committed, so `git log --show-signature` has no local verification file.
- `~/.config/mise/config.toml` is symlinked to `home/dot-config/mise/config.toml`; edits are live and `mise bootstrap` re-reads it and installs tools.
- The same file's `[env]` block keeps tool data and caches under `~/.local/share` and `~/.cache` instead of the home root: `GOPATH`, `GOMODCACHE`, `GOCACHE`, `GOBIN`, `CARGO_HOME`, `RUSTUP_HOME`, `BUN_INSTALL`, `BUN_INSTALL_CACHE_DIR`, plus the cargo `bin` directory on `PATH`. It also defines `HOME` from `USERPROFILE` on Windows, where `HOME` is unset; `~` is not expanded in `[env]` values, so the resolved path is stored and later entries reuse it. `mise run env` mirrors the block into the Windows user environment (HKCU `Environment`) so editors and GUI apps see the same paths; `mise run env:check` reports drift. Restart the shell and editors after changing it.
- `mise run system` executes the declarative OS-state resources under `scripts/system/resources/{common,<os>}/` (deployed to `~/.local/share/t128n-dotfiles/scripts/system`). It is a dry run unless `--apply` is passed.
- `~/.config/opencode` is deployed with `symlink-each`. Only config files belong in `home/dot-config/opencode`; never add `service.json`, `cli.json`, `opencode.json`, or `*.bak`.
- `git config --global` ignores `include.path` unless `--includes` is passed; use `git config user.name` or `git config --global --includes --list` in scripts.
- `~/Documents/PowerShell/Microsoft.PowerShell_profile.ps1` is symlinked to `home/dot-config/powershell/Microsoft.PowerShell_profile.ps1`. It activates mise, configures PSReadLine, runs `starship init powershell`, then dot-sources `~/.config/powershell/profile.local.ps1` if present. That local file is per-machine and never committed. The Windows PowerShell 5.1 profile is not managed.
- `~/.config/starship.toml` is symlinked to `home/dot-config/starship.toml`. The config uses the Oxocarbon palette to match Windows Terminal; `starship` itself is installed from `home/dot-config/mise/config.toml`.
- Windows Terminal `settings.json` is symlinked from the Store package path (`~/AppData/Local/Packages/Microsoft.WindowsTerminal_8wekyb3d8bbwe/LocalState/settings.json`). The settings UI writes through the link but does not hot-reload it until Terminal restarts. Terminal may rewrite the file during version migrations, so review and commit the diff afterwards. Preview and unpackaged installs use different paths.
- `home/dot-config/espanso/{config/default.yml,match/base.yml}` is symlinked to `~/.config/espanso/...` on every OS. Espanso checks `~/.config/espanso` before its platform default, so this keeps one path across machines. `base.yml` holds the German umlaut and Eszett triggers; `default.yml` disables the toggle key and enables auto-restart. Run `espanso restart` after editing the source because Espanso watches the live config directory, not the symlink target.
